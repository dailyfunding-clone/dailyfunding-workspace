## 1. 개요

데일리펀딩(new.daily-funding.com / www.daily-funding.com)을 벤치마크한 온라인투자연계금융(온투업, P2P 금융) 플랫폼을 직접 설계·구현한다. 투자자가 상품을 조회하고 예치금으로 투자하면, 대출 실행 후 매월 원리금이 상환되는 전체 생명주기를 실제 동작하는 코드로 만든다.

### 1.1 목적

- 금융 도메인의 정합성·동시성·멱등성 문제를 직접 설계하고 측정 가능한 결과를 남긴다
- 웹 + WebView 앱 + 디자인 시스템 + OpenAPI 계약까지 갖춘 서비스 수준의 산출물을 만든다
- 실제 은행·인증 연동이 불가한 부분은 모의 시스템으로 대체하되, 경계(웹훅·서명·재시도)는 실제 연동과 동일하게 설계한다

### 1.2 배경

실서비스 기능 분석(feature-map.md)에서 플랫폼은 투자·대출·마이페이지·콘텐츠 네 축으로 구성된다. 실제 서비스는 신규 Next.js 사이트와 레거시 PHP 사이트가 공존하는 마이그레이션 진행 중 상태이며, 본 프로젝트는 신규 사이트 방향을 기준으로 단일 아키텍처로 통합 설계한다.

## 2. 사용자

| 역할 | 설명 |
|---|---|
| 투자자(개인) | 상품 조회·투자·상환 수령. 등급(일반/소득적격/전문)에 따라 투자 한도가 다름 |

## 3. 범위

### 3.1 포함 (In Scope)

**회원/인증**
- 이메일 회원가입(투자자/대출자 구분), 로그인, 로그아웃
- 간편비밀번호 6자리 등록·로그인, 앱 내 생체인증 로그인
- 본인인증(모의): PASS 흐름을 모사한 인증 단계
- 회원정보·계좌 관리는 비밀번호 재확인(2차 인증) 게이트 통과 후 접근

**투자**
- 투자 상품 목록: 상세검색(모집 상태·수익률 정렬·기간/금액 범위), 유형 필터, 진행률 표시
- 투자 상품 상세: 모집 정보, 탭(종합정보/상세정보/유의사항)
- 예상수익 계산기: 투자금액 입력 → 세전/세후 수익, 회차별 상환 스케줄 표
- 투자 주문: 한도 검증(등급 한도·동일차주 한도·잔여 모집액), 예치금 차감, '네' 입력 최종 확인
- 투자적합성 테스트: 6문항 게이트, 미통과 시 투자 차단, 1년 유효
- 장바구니: 상품 담기/조회/삭제, GNB 건수 뱃지
- 예약 투자: 만기 상품 재모집 시 원금 자동 재투자 예약

**예치금 / 가상계좌**
- 가상계좌 발급(은행 코드 + 계좌번호), 계좌 정보 조회
- 입금: 모의 은행 모듈이 입금 웹훅을 API로 발송 → 서명 검증 → 매칭 → 원장 반영
- 출금: 출금 요청 → 원장 홀드 → 모의 은행 이체 → 완료. 수수료 정책(월 20회 면제, 이후 건당 500원)

**포인트**
- 포인트 원장: 적립·사용·소멸 전부 분개 처리
- 이벤트 적립(친구 추천 등), 투자 시 포인트 사용, 당월 소멸 예정 조회, 소멸 배치

**마이페이지**
- 대시보드: 프로필·등급·인증 상태, 가상계좌, 예치금, 포인트, 남은 투자한도, 투자 요약
- 상환달력: 월별 상환 원금/이자 집계 캘린더
- 투자내역: 상태·유형 필터 / 예치금내역: 기간 조회·원천징수영수증·플랫폼이용료 / 포인트내역: 소멸 예정·엑셀 저장
- 등급정보·등급 변경 신청, 원스톱 한도심사(서류 제출 모의)

**대출**
- 대출 상품 소개(상품별 대상·한도·금리·상환방식·수수료 표)
- 간편 한도 조회(모의 심사), 대출 신청 폼(2단계)

**콘텐츠**
- 공지사항(카테고리·검색·첨부파일), FAQ(카테고리·검색·아코디언)
- 이벤트(상태 탭·참여 CTA), 공시(경영현황·운영현황·내부통제 탭), 언론보도, 약관

**앱**
- Expo React Native 셸 + WebView 화면 조합
- 네이티브가 담당하는 영역과 WebView가 담당하는 영역을 명시적으로 분리해 네이티브 경험 확보
- 타입드 JS↔Native 브릿지: 생체인증 로그인, 푸시 알림(신규 상품 오픈/모집 마감), 공유

**운영자**
- 상품 CRUD·모집 상태 관리, 모집 완료 시 대출 실행 처리
- 상환 스케줄 생성·정산 배치, 공지/FAQ/이벤트/공시 관리

### 3.2 제외 (Out of Scope)

- 실제 금전 이동(은행 API, PG 연동) — 모의 은행 모듈로 대체
- 실제 본인인증·간편인증 연동 — 모의 인증 단계로 대체
- 신용조회, 보증보험 연동
- 자동투자(실서비스에도 없음), 1:1 문의 게시판(실서비스는 카카오톡 채널 사용)
- 앱 스토어 배포(Expo 빌드 + 시연 영상으로 대체)

## 4. 핵심 플로우

### 4.1 투자 생명주기

```
회원가입(투자자) → 본인인증(모의) → 가상계좌 발급 → 입금(모의 은행 웹훅)
→ 투자적합성 테스트 → 상품 탐색/장바구니 → 투자 주문(한도 검증 + 멱등)
→ 예치금 차감(원장 분개) → 상환 스케줄 생성
→ 모집 100% → 대출 실행 → 매월 상환 배치(원금+이자 → 예치금 원장 반영)
→ 만기/연체/조기상환 처리 → 예약 투자 시 재투자
```

### 4.2 대출 신청

```
대출 상품 선택 → 간편 한도 조회(모의) → 신청 폼 제출(2단계) → 운영자 심사 큐
→ 승인 시 상품화 → 투자 모집 오픈
```

## 5. 성공 지표

### 기능
- 투자 생명주기 전 구간이 실제 데이터로 end-to-end 동작
- 웹/앱/디자인 시스템이 하나의 계약(OpenAPI)으로 연동
- 운영자가 상품 등록부터 정산까지 UI로 운영 가능

### 기술(측정 목표)
- 모집 잔액 경합: 동시 투자 부하 테스트(k6)에서 초과 모집 0건, 중복 주문 0건
- 멱등성: 동일 멱등 키 재전송 시 투자 건 1개만 생성
- 상환 정합성: 스케줄 총합 = 원금+이자 합계, 원장 차대변 일치 검증
- 앱 첫 화면 표시 시간을 측정하고 적용 기법별 개선 수치 확보
- OpenAPI 스키마-프론트 타입 불일치 시 CI 실패

- 실행 가능한 웹·앱·API·모의 은행 + 시드 데이터
- 부하 테스트·동시성/정합성 검증 리포트
